## 2024-05-15 - Hardcoded JWT Secret Key in Configuration
**Vulnerability:** The `JWT_SECRET_KEY` was hardcoded in `config.yaml` and loaded directly without allowing environment variables to override it. This meant the same secret key would be used across all environments, making the application vulnerable to token forgery if the configuration file or the source code repository were compromised.
**Learning:** Hardcoding secrets directly in configuration files within source control is a severe security risk. The `backend/config.py` did not provide an abstraction to pull secrets securely from the environment, leading developers to rely on the static file configuration for sensitive data.
**Prevention:** Always read sensitive credentials, such as database passwords, API keys, and JWT secrets, from environment variables (e.g., `os.environ.get("JWT_SECRET_KEY")`). Static configuration files should only contain default or non-sensitive settings. Ensure CI/CD pipelines and deployment environments are configured to inject secrets securely as environment variables.
