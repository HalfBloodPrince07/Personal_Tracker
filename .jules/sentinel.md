## 2024-05-24 - JWT Token and Secret Key Leakage in Auth Logging
**Vulnerability:** Debug print statements in `backend/auth.py`'s `get_current_user` dependency leaked the raw JWT token, the decoded payload, and the first 5 characters of the secret key to standard output on authentication failures.
**Learning:** Development debugging patterns involving print statements or excessive logging can inadvertently capture and expose highly sensitive credentials in production logs.
**Prevention:** Remove debug `print` statements before committing auth code. Use standard `logging` with appropriate levels (e.g., `logger.warning`) and ensure that secrets, tokens, or raw payloads are never logged. Log only actionable, non-sensitive context (e.g., "Invalid token for user ID X" rather than the token itself).
## 2026-10-02 - [CRITICAL] Fix Hardcoded JWT Secret Vulnerability
**Vulnerability:** A hardcoded `secret_key` ("plis-super-secret-key-change-in-production-2024") was found in `config.yaml` for JWT authentication. This could allow an attacker to forge JWT tokens if they gained access to the source code or configuration files.
**Learning:** Hardcoded secrets in configuration files that are checked into version control are a significant security risk. Configuration files should only contain environment-agnostic settings or placeholders for secrets, which should be injected at runtime via environment variables or a secure secret management system.
**Prevention:** Ensured the backend configuration (`backend/config.py`) explicitly requires the `JWT_SECRET_KEY` environment variable to be set and fails fast with a clear error message if it's missing. The `config.yaml` file was updated to remove the hardcoded secret and document the requirement for the environment variable.
