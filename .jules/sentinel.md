## 2025-03-05 - [Fix Data Leakage and Secret Configuration in Backend]
**Vulnerability:** A hardcoded `JWT_SECRET_KEY` was not overridable by environment variables in `backend/config.py`, meaning it would rely on a static secret defined in `config.yaml`. Furthermore, `backend/auth.py` contained debug `print` statements that explicitly dumped the user's JWT token, JWT payload, and a portion of the application's secret key into the standard output stream whenever a JWT error occurred or a user_id was missing.
**Learning:** Hardcoding secrets makes rotation difficult and increases the likelihood of accidental commit in public repositories. Dumping secrets to logs (even for debugging) poses a severe risk as log files can be widely accessible and persisting. Developers often leave debugging code in production.
**Prevention:** Avoid explicitly logging tokens, keys, and payload contents. All application secrets should be configurable and loaded from secure environment variables, with fallback defaults used cautiously. Implement robust security linters or code review practices to detect debugging prints left in sensitive functions.
