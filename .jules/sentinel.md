## 2024-05-24 - [CRITICAL] Prevent JWT Token and Secret Key Leakage
**Vulnerability:** In `backend/auth.py`, the `get_current_user` dependency leaked sensitive information (the JWT token and the first 5 characters of `SECRET_KEY`) to standard output via `print()` statements when a `JWTError` exception occurred. Additionally, the default secret key from `config.yaml` was not easily overridable securely via environment variables.
**Learning:** Debugging statements left in production code can easily expose sensitive credentials in logs or console output, which is a critical risk, especially for authentication tokens and symmetric keys. Also, relying solely on file-based configuration for secrets without environment variable overrides makes secure deployment difficult.
**Prevention:** Never log raw tokens, passwords, or secret keys (even partial ones). Always ensure that secrets defined in configuration files can be securely overridden by environment variables (e.g., `JWT_SECRET_KEY`) in production environments.
